# Demo 18 - GitHub Copilot App (Desktop)

This starter demonstrates how the GitHub Copilot desktop app coordinates Python
coding work as visible, reviewable sessions. Two independent methods intentionally
raise `NotImplementedError`; `TASK.md` and the focused pytest files define the
expected behavior.

The split is deliberate: the sprint-planning and risk-analysis workstreams can
run in parallel without editing the same test files.

## Prerequisites

- Python 3.12 or later
- pytest (`python -m pip install pytest`)
- Git installed and this repository cloned locally
- GitHub Copilot app installed on Windows or macOS
- An active GitHub Copilot subscription and a signed-in GitHub account

Before presenting, run this command from the demo folder. Six tests should fail
because the two methods are unfinished:

```powershell
python -m pytest -q
```

## Live demo

1. Open the GitHub Copilot app and add this repository as a workspace. Select
   `Python/18-github-copilot-app` as the working folder if the app offers folder
   scoping. Explain that the app is a control center for agent sessions, while
   the repository remains the source of truth.

2. Start a planning session with this prompt:

   ```text
   Read TASK.md, the source modules, and the tests. Explain the two
   independent workstreams, identify their acceptance criteria, and propose a
   validation plan. Do not edit files yet.
   ```

   Review the plan and show the files the session used as context before
   authorizing implementation.

3. Start two implementation sessions so the audience can see work progressing
   in parallel.

   **Session A:**

   ```text
   Implement only Workstream A from TASK.md. You may edit sprint_planner.py and
   test_sprint_planner.py only. Keep the public API unchanged and run the focused
   SprintPlanner tests. Summarize the behavior and test results when finished.
   ```

   **Session B:**

   ```text
   Implement only Workstream B from TASK.md. You may edit risk_analyzer.py and
   test_risk_analyzer.py only. Keep the public API unchanged and run the focused
   RiskAnalyzer tests. Summarize the behavior and test results when finished.
   ```

   Point out each session's status, isolated changes, command activity, and
   completion summary. The exact labels and controls can vary by app version.

4. Open each completed session. Review the diff before accepting or applying
   it, and verify that the agent stayed within its assigned code and test scope.
   Ask a follow-up in the relevant session when a requirement or test is unclear.

5. After both changes are available together, start an integration session:

   ```text
   Review the combined changes against every requirement in TASK.md. Do not
   change code unless you find a concrete defect. Run python -m pytest -q and
   report any unmet acceptance criterion with file evidence.
   ```

6. Show the final diff and pytest result. Explain that session summaries make it
   easy to move between tasks, but the human still decides what to keep and what
   is ready to commit or open as a pull request.

## Reset after the demo

From the repository root, restore only this demo and remove files generated by
the agent:

```powershell
git restore Python/18-github-copilot-app
git clean -fd Python/18-github-copilot-app
```

Review untracked files before using `git clean` on a shared working tree.

## Talking points

- The desktop app gives multiple agent sessions a single, visual control center.
- Splitting work by acceptance criteria and test files makes parallelism useful
  and reduces conflicting edits.
- A session is an auditable unit: prompt, context, tool activity, diff, tests,
  and summary stay together.
- Repository instructions and tests travel with the code; chat history alone is
  not a specification.
- Agent completion is not approval. Review the diff and run executable checks
  before committing or opening a pull request.
- Use the CLI for terminal-native work, the IDE for editor flow, and the desktop
  app when coordinating and monitoring multiple coding sessions is the focus.
